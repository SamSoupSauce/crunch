# Changelog 001: Online Multiplayer & Session Coordination

**Date:** 2026-10-01  
**Scope:** Multiplayer Backend, Web Client Integration, and Session Management

---

### Highlights

- **Multiplayer Go REST Server (`server/`)**:
  - Implemented 24-hour room lifecycles with automated periodic Janitor cleanup.
  - Enforced strict player turn coordination (Player 1 moves first, alternating turns).
  - Integrated REST endpoints for messaging and move synchronization without arbitrary data validation.

- **Host & Slot Enforcement**:
  - Host is automatically assigned as Player 1 upon room creation (`POST /rooms`).
  - Added `GET /rooms/{id}/slots` endpoint enabling joining players to query available slots before entering.
  - Room joining restricted to Player 2 when Player 1 is occupied.
  - Implemented 5-minute inactivity slot reopening: if the active turn stalls for >5 minutes, the slot reopens for new player takeover.

- **Stateless Client Session Management (`session.js`)**:
  - Lightweight, dependency-free role resolution (`resolvePlayerRole`, `persistSession`, `clearSession`).
  - Room persistence keyed by `roomCode` with tab-scoped session recovery.
  - Automatic session cleanup on match completion or room departure.

- **Web Client Integration (`index.html`)**:
  - Added multiplayer lobby modal with Host and Join controls, room code sharing, and slot picker.
  - Added live spectator mode for rooms with both player slots claimed.
  - Added in-game chat messaging panel and synthesized Web Audio sound engine.
  - Implemented deep-link room auto-join via `?room=ROOM-...` URL parameters.

- **Automated Verification**:
  - Full Go unit and API integration test suite covering room lifecycles, concurrency, slots, and inactivity timeouts (`go test ./...`).
  - Node.js test suite verifying client-side session resolution and recovery (`test_session.js`).
